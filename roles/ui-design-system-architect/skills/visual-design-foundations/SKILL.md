# Visual foundations for Role 2A

Condensed adaptation of [Seth Hobson visual design foundations](https://github.com/wshobson/agents/blob/main/plugins/ui-design/skills/visual-design-foundations/SKILL.md), consulted 2026-11-01. MIT notice: `../LICENSES.md`.

Compare three coherent styles using the same content and layout constraints. Give each an explicit canvas/surface/text/accent palette, type treatment, visual density and proof treatment. Explain trade-offs in five-second clarity, reading comfort, technical character and implementation weight. Recommend one for founders and CTOs without claiming user approval.

Choose a restrained type pairing from the existing Geist/Syne/JetBrains Mono baseline or justify a change with a source, fallback and Role 2B availability check. Specify exact mobile/desktop sizes, line heights and weights; small text remains at least 14px and body text at least 16px.

Use a small spacing/radius scale and one consistent icon treatment. Accent marks actions and meaningful state; labels and shapes also communicate state. Proof comes from real screenshots and source-backed architecture diagrams.

Apply the W3C formula through the deterministic helper: 4.5:1 for project text policy and 3:1 for necessary UI indicators. Glass/decorative effects must not change calculated text backgrounds. All content-bearing surfaces are opaque.

Respect the audited layout's complete headings, proof pills and mobile budgets. Treat line-wrap predictions as assumptions for canvas measurement, never completed tests. Stop at the written design system; Role 2B owns screen construction.
