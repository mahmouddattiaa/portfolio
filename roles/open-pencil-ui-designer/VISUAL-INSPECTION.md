# Visual inspection comes before moving on

After completing a section or page, export a screenshot, open the actual image, and inspect it before starting the next section or page. Do this throughout the work, not only at the end. A successful tool call, saved file or clean lint result does not prove the design looks correct.

## Required loop

1. Export the completed section/page from the actual Open Pencil document. Use its real node ID and save under `design/reviews/`, or a permitted location recorded in the handoff.
2. Open and inspect the image with an image-viewing tool. Keep text readable at the inspection size. A tiny full-page overview cannot prove paragraph or button fit; add section exports or close-ups.
3. Check full text and fonts, clipping, overlap, spacing, alignment, image proportions, missing elements, button labels and visual states. Compare visible copy and assets with the locked sources.
4. Fix visible problems in the editable document. Export a new screenshot and inspect it again to confirm the correction.
5. Record the section/page, node ID, screenshot path, issue found and fix, and the final result. Then continue.

Apply the loop to desktop and mobile versions, detail pages, component/state boards and motion studies. For work already built, inspect it before marking it complete. Recheck affected screens when a shared component or font changes.

## What to look for

- Full headings, proof pills, descriptions and action labels fit naturally. Text is never clipped or shrunk to make a screenshot pass.
- Fonts render correctly, including Arabic examples; missing glyphs and silent substitutions are reported.
- Cards, images, diagrams and controls stay within their intended frames without unwanted stretching or overlap.
- Expanded disclosures, errors, selected states and focus outlines remain readable and correctly placed.
- First-view frames stay at 1440x900 and 390x844. Record any missed fold target; extending the image does not fix it.
- Background shapes and motion examples do not obscure content. Static screenshots demonstrate appearance, not live animation.

## Honest results

If the export or image-viewing tool is blocked, say which check could not be completed. Keep it unverified and preserve the current design; do not mark the section visually passed. Follow the role's retry limit and work on independent items if possible.

Test supported interactive controls separately. Screenshots cannot prove keyboard behavior, browser history, real form submission, responsive browser layout or animation performance. Keep those checks separate in the handoff.
